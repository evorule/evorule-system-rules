# 设计规范(adr/)

> 目录说明:本目录存放**已定型的设计规范**。每篇规范回答三个问题:
> 是什么、为什么、怎么用。不展示决策过程。

## 与传统 ADR 的区别

| 项目 | 传统 ADR(决策日志) | 本目录(设计规范) |
|------|--------------------|-------------------|
| 受众 | 团队内部 review | 公开读者 / 团队成员 |
| 风格 | 草案、讨论、权衡 | 结论、规格、说明 |
| 内容 | 候选方案 A/B/C、决策过程、后果 | 是什么、为什么、怎么用 |
| 目的 | 记录决策 | 传达规范 |
| 不确定性 | 包含 | 避免 |

**本目录的规范一经发布即为定论**。如有变更,写新规范并 supersede 旧的,不改原文。

## 适用对象

设计规范适用于以下情形:
- 字段定义、命名规则等基础规范
- 协议版本规则
- 跨仓 / 跨工具的对齐约束
- 系统架构边界

不适用于:
- ❌ 具体功能实现细节
- ❌ 内部流程 / 工具脚本用法
- ❌ 临时性决策

## 命名规范

`主题名.md`(用英文 kebab-case 描述主题,避免编号):
- ✅ `five-top-level-fields.md`
- ❌ `0001-five-top-level-fields.md`(无编号)

## 写作模板

每篇设计规范的结构:

```markdown
# <规范名>

## 是什么

[规范定义,简明扼要]

## 为什么

[简短理由,3-5 条]

## 怎么用

[指向 reference 或 tutorial 的链接]

## 不接受的替代方案

[1-2 句话点明被排除的方案,避免读者疑惑]
```
